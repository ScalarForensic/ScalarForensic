## Executive Summary

**Grade: B** — Healthy, unusually well-documented codebase with a strong safety culture — and one structural debt concentrated exactly where it hurts most.

ScalarForensic is in good shape for a two-maintainer forensic tool: the suite is fast and hermetic (530 tests in 8 seconds), CI enforces lint, format, and tests, comparability safeguards fail fast on config drift, file serving fails closed, and the documentation culture is the best part of the repo. The grade is B rather than A because the risk is inverted: the *write path* — the code that puts evidence into the database — is the least-tested, most-complex code in the project. `cli.py`'s `index()` is a single ~1,490-line function at 40% module coverage, and `indexer.py`, the module that actually writes Qdrant points, sits at 17%.

**Top 3 risks:** (1) an ingest regression in `index()`/`indexer.py` would ship with today's tests green; (2) the face-exclusion guarantee — a court-facing property — is only verifiable by 5 tests that never run in CI; (3) the unvetted `httpx2` dev dependency is installed in every dev and CI environment.

**Top 3 opportunities:** (1) a Qdrant service container in CI turns the 5 skipped integration tests into a permanent gate for ~20 lines of YAML; (2) decomposing `index()` into testable stages makes every future ingest feature cheaper and safer; (3) removing sync Qdrant/file I/O from async handlers fixes UI responsiveness under concurrent examiners.

## Repo Map

**Purpose:** forensic image/video similarity search — index evidence directories into Qdrant with DINOv2 (semantic) + SSCD (copy-detection) embeddings, optionally faces; query via a web UI. Two maintainers; features must be legible to reviewers and courts. Maturity: a serious internal tool moving toward production deployment on isolated LANs — well past prototype.

**Stack:** Python 3.12 (pinned), uv + uv.lock, FastAPI/uvicorn, Qdrant, PyTorch (CUDA 12.8 index; ROCm documented), OpenCV+ONNX for faces, Alpine.js frontend (no build step), pytest + ruff, GitHub Actions CI, Dockerfiles for airgapped bundles.

**Flow:** CLI `sfn` (`cli.py:index()`) → scan/hash/dedup (`discovery.py`, `embedder.py:HashCache`) → embed (`embedder.py`) → upsert (`indexer.py`), plus optional faces (`faces/*` → `faces/store.py`). Web `sfn-web` (`web/app.py`) → routers in `web/routes/` → pipeline package `web/pipeline/` → Qdrant. Sessions are in-memory with a TTL reaper (`web/session.py`).

| Area | What it is |
|---|---|
| `src/scalar_forensic/` | Core: config, CLI, embedders, indexer, safeguards, calibration, video, tags |
| `src/scalar_forensic/faces/` | Face modality: detect → quality gates → align → embed → store (review-only observations stay vectorless) |
| `src/scalar_forensic/web/` | FastAPI app, per-topic routers, pipeline package, Alpine frontend split into part files |
| `tests/` (9,017 lines) | Hermetic suite + env-gated Qdrant integration tests |
| `docs/` | Specs, math notes, deployment, research — mixed with fleet logs, handoffs, QA screenshots |
| `scripts/`, `run.sh` | Model downloads, airgap bundling, CUDA lib wrapper |

**Surprises:** the documentation-to-code ratio is remarkably high and mostly accurate; the known Qdrant limitation (no incremental named vectors) is honestly encoded as a hard error with remediation text (`indexer.py:96-108`); and a dependency named `httpx2` sits in the dev group where `httpx` was almost certainly intended.

## Audit Report

Each finding is labeled *fact* (verified in the file cited) or *judgment* (my assessment). No Critical findings were identified. Dimensions with nothing material to report are stated in one line.

### Testing

#### [High / fact] The ingest write path is the least-tested code in the repo

Coverage: `indexer.py` 17%, `cli.py` 40% (dominated by `index()`), `calibration.py` 13%, `web/pipeline/analysis.py` 26%, versus 80–95% on the faces modules. The code that writes evidence points — dedup decisions, point-ID derivation, the update-vs-insert split in `indexer.py:409-448` that avoids wiping the other model's vector — is mostly exercised only by real indexing runs.

*Why it matters:* a regression here corrupts or silently skips evidence during ingestion, the one phase you can't re-run against seized media at trial time, and today's suite would stay green.

#### [Medium / fact] The face-exclusion guarantee is never verified in CI

`tests/faces/test_store_integration.py` (and 4 siblings) skip unless `SFN_TEST_QDRANT_URL` is set; `.github/workflows/ci.yml` has no Qdrant service, so the only tests that can observe the vectorless-point guarantee against a real store run only when a maintainer remembers to run them.

*Why it matters:* this is the property CLAUDE.md itself calls the guarantee with evidential consequence. A refactor of demotion/purge could break it and pass CI.

#### [Low / judgment] No automated browser tests for a substantial frontend

~2,000 lines of Alpine part files + 2,186-line `index.html` are verified by manual Playwright sessions whose screenshots are committed under `docs/qa/`. The static-wiring test (`tests/faces/test_static_wiring.py`) is a good partial mitigation. Acceptable at this team size; noted, not urgent.

### Architecture & code quality

#### [High / fact] `index()` is a ~1,490-line function

`cli.py:359` through ~`cli.py:1847`: one Typer command containing option parsing, config validation, scanning, hashing, dedup, batch calibration, image/video/faces pipelines, progress/ETA rendering (with nested defs at `cli.py:738` and `cli.py:957`), CSV reporting, and summary printing. It is the direct cause of the coverage finding above — nothing inside it can be tested without invoking the whole command.

*Why it matters:* every ingest change (like the recent embed-floor change) means editing a function no one can hold in their head, with no unit-level safety net. This is the repo's single ugliest part and its highest-leverage refactor.

#### [Medium / fact] Sync Qdrant and file I/O inside async handlers blocks the event loop

`routes/analyze.py:168` calls `query_session()` — which does synchronous Qdrant network I/O, potentially one query per video frame (`pipeline/query.py:267`) — directly inside `async def query`, the endpoint hit on every slider change. Same pattern: sync `client.scroll` at `routes/files.py:447-462` and `files.py:524-539`, and full-file `read_bytes()` + SHA-256/MD5 of arbitrary-size evidence files at `files.py:490-495`, all in the event loop. Inconsistent, because the codebase clearly knows the right pattern — `asyncio.to_thread` is used correctly in `tags.py`, the thumbnail-regen path, and the analysis task.

*Why it matters:* with up to 32 concurrent sessions (config.py:156), one examiner dragging a threshold slider stalls every other examiner's requests, including image loads.

#### [Medium / fact] Duplicated frame-metadata logic

The video-frame branch of `hit_metadata` (`routes/files.py:434-485`) and `frame_metadata` (`files.py:499-561`) contain a nearly identical Qdrant lookup + metadata assembly block. They have already drifted stylistically and will drift behaviorally.

#### [Medium / fact] A new `QdrantClient` per request, at 13 call sites

Every handler/pipeline call constructs a fresh client (e.g. `pipeline/query.py:267`, `routes/tags.py:46`, `routes/files.py:157/447/524`) — a new connection pool per request, and 13 places to keep in sync when auth or TLS options change. Judgment on severity: on a LAN this is latency noise, but it compounds the blocking finding and is cheap to fix with one lifespan-managed client.

#### [Low / fact] Two silently swallowed exceptions

`routes/files.py:467-468` and `files.py:543-544`: `except Exception: pass` around Qdrant lookups. The fallback behavior (serve partial metadata) is right; the silence is not — a down Qdrant looks identical to a missing record. One `_log.debug` each, matching the pattern already used at `files.py:170-171`.

#### [Low / fact] Nine copy-pasted payload-index blocks

`indexer.py:118-177`: nine sequential `if "field" not in schema:` blocks that differ only in name and type — a dict + loop. Cosmetic, fold into the refactor.

#### [Low / judgment] No type checking in CI

Annotations are pervasive and good, but nothing verifies them (no mypy/pyright step in `ci.yml`), and escape hatches like `query_faces_cfg: object` (`web/session.py:66`) go unchecked. The annotation investment is already paid; the checker is the missing 10%.

### Security

#### [Medium / fact] Unvetted `httpx2` package in the dev group

`pyproject.toml:36` declares `httpx2>=2.7.0` — a separate PyPI package ("The next generation HTTP client", installs module `httpx2`), imported nowhere in the repo. The real `httpx` 0.28.1 arrives transitively (via `qdrant-client`, uv.lock:880), which is why `TestClient` works. Almost certainly a typo for `httpx`.

*Why it matters:* an obscure third-party fork with its own transitive tree (`httpcore2`, `truststore`) is installed into every dev machine and CI runner of a forensic tool. Whatever its intentions, it's unaudited surface bought for nothing. Verified safe to swap: no source file imports it.

#### [Low / fact] Otherwise healthy — deliberate risks are documented, mechanical controls are sound

File serving fails closed and path-checks by `Path.relative_to` on resolved paths, not string prefixes (`routes/_shared.py:12-38`); upload size and session caps exist (`config.py:146,156`); MD5 is corroborative and marked (`files.py:417`); no secrets are tracked (`.env` is gitignored; only `.env.example` is committed); HuggingFace is offline-by-default (`config.py:335-355`). The 0.0.0.0 bind and unauthenticated API are recorded architecture decisions for isolated LANs — accepted per `docs/deployment.md`, not re-flagged.

### Performance

Healthy apart from the event-loop finding above: dedup scrolls are single-pass with O(1) lookups (`indexer.py:179-215`), hashes are cached by (path, mtime, size), thumbnails are pre-generated, and batch size is auto-calibrated. No N+1 patterns found in the paths reviewed.

### Dependencies

Healthy apart from `httpx2`: recent pins, committed `uv.lock`, Dependabot configured, licenses tracked in `THIRD_PARTY_LICENSES.md`. One efficiency note (unverified duration): CI's `uv sync --dev` resolves torch from the CUDA 12.8 index on a CPU-only runner, downloading multi-GB wheels; the cache mitigates but a CPU-index CI override could cut cold-run time materially.

### DevEx & documentation

#### [Low / fact] Small doc debts in an otherwise excellent doc set

`CONTRIBUTING.md` is one line; CLAUDE.md's suite bar (478/5, dated 2026-08-12) is already stale versus the measured 530/5 — ironic given the repo's own rule about attributing bars to SHAs. *Judgment:* `docs/` increasingly mixes durable reference (specs, math, deployment) with process journal (fleet logs, handoffs, QA screenshots, CTO ledger); fine for two maintainers, but a `docs/journal/` split would keep the reference set findable.

### Strengths — preserve these

- **Comparability safeguards:** both entry points refuse to start when models/normalize-size/crops drift from what the collection recorded, with actionable remediation text (`web/app.py:96-228`, `safeguards.py`). This is the forensic core done right.
- **Structural exclusion over flags:** review-only faces are vectorless points — kept out of search by construction, not by a filter someone could forget (`web/session.py:26-47`, faces store).
- **Fail-closed file serving** and offline-by-default network policy.
- **Fast hermetic suite** (530 tests, 8.3 s, no Qdrant needed) — refactoring fuel.
- **Error messages written for humans:** the incremental-modality error (`indexer.py:101-108`) and face-startup errors explain the constraint and the fix.
- **Documentation culture:** specs with recorded rulings (uncalibrated face scores, §10), measured config defaults (the crop-dilation comment in `.env.example`), honest gotcha logs.
- **Clean web layering:** per-topic routers, pipeline package with a re-exported public API, frontend part-file convention consistently followed.

## Improvement Strategy

### Theme 1 — Invert the test/complexity mismatch on the write path

*Principle:* in a forensic tool, the code that writes evidence deserves the strongest tests, not the weakest. *Target state:* `index()` decomposed into pure, importable stages (scan/dedup → batch embed → upsert → report) with the Typer command as a thin shell; `indexer.py` unit-tested against a mocked client for the update-vs-insert and provenance logic. *Done when:* `indexer.py` ≥ 80% and the extracted ingest stages ≥ 75% coverage; `index()` body under ~150 lines.

### Theme 2 — Make the guarantees CI-enforced, not maintainer-remembered

*Principle:* a guarantee that isn't executed on every merge is a hope. *Target state:* CI runs the 5 Qdrant-gated integration tests against a service container; a coverage floor exists so the write path can't silently regress. *Done when:* CI fails if the exclusion guarantee breaks; zero permanently-skipped tests on the main workflow.

### Theme 3 — Async discipline and one Qdrant client

*Principle:* the web tier already knows the right pattern; apply it uniformly. *Target state:* no synchronous Qdrant/file I/O executes on the event loop; one lifespan-managed client (or a small provider) replaces the 13 constructions. *Done when:* grep finds no `QdrantClient(` outside the provider, and slider-change queries run in a thread.

### Theme 4 — Supply-chain hygiene

*Principle:* an evidence tool's dev environment is part of its trust story. *Target state:* every dependency is one the maintainers can name a reason for. *Done when:* `httpx2` is gone and the suite still passes.

### Deliberately not fixing

- **Authentication / bind address** — recorded architecture decision for isolated LANs; re-litigating it is out of scope.
- **The 2,186-line `index.html` and CSS monolith** — no build step is itself a deployment feature for airgapped use; the JS part-file convention already contains the growth. Cost of a bundler exceeds the payoff at this team size.
- **`calibration.py` coverage (13%)** — hardware-probing code; meaningful tests would be mocks testing mocks.
- **Full `tags.py` refactor** — 970 lines but working and behind good route boundaries; raise its test coverage opportunistically rather than restructure now.
- **MD5, pytest torch warnings, E402 in scripts** — all intentional and documented.

### Implementation sketches — top 3

**T1 (httpx2 swap):** change `pyproject.toml:36` to `"httpx>=0.27"`, run `uv sync --dev`, confirm `httpx2`/`httpcore2` leave `uv.lock`, run the suite. Gotcha: none — verified that no file imports `httpx2` and that `httpx` is already a transitive dependency of `qdrant-client`, so `TestClient` behavior cannot change.

**T2 (CI integration job):** add a second job with `services: qdrant: image: qdrant/qdrant, ports: [6333:6333]`, env `SFN_TEST_QDRANT_URL=http://localhost:6333`, running `uv run pytest tests/faces/test_store_integration.py` (plus the other gated tests). Gotchas: give Qdrant a health-check/retry loop before pytest; keep the job separate from the hermetic one so the fast suite stays fast; use a throwaway collection name per run since the tests write.

**T4 (unblock the event loop):** in `routes/analyze.py:query`, change the call to `results, models = await asyncio.to_thread(query_session, ...)`; in `files.py`, move the two scroll blocks and the `read_bytes`+hash sequence into local functions passed to `to_thread` (the file already does this correctly in `_try_regenerate_thumbnail` — copy that shape). Gotcha: `query_session` reads session entries that the analysis thread may still be populating; confirm the mutation points (the analyze task writes embeddings before marking the file ready) or snapshot the entries list before dispatching.
